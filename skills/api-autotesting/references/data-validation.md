# 真实业务数据准确性验证

本文件承载接口路径验证与真实业务数据验证的边界，以及二期数据验证路由。由 SKILL.md 按任务路由加载。

## 一期与二期数据准确性验证路由

先判断用户真正要验证的是**接口执行/代码分支行为**，还是**真实业务数据结果**；接口新增、修改或首次初始化本身不决定是否进入二期。

- **一期：源码驱动的场景发现与回归**。验证请求能否按预期执行、参数/条件分支是否正确触发、异常处理及必要响应行为。可用不依赖真实业务记录的输入验证参数校验和代码路径；不要求为每个参数场景造数，不默认执行 SQL、INSERT 或 ETL。
- **转入二期的条件**：目标需要证明真实金额、重量、数量、字段转换、业务过滤、关联、聚合、同步等数据结果，或某分支必须依赖真实记录才能有效触发。保留对应场景并标记 `BLOCKED`/`NOT_VERIFIED`，不能用接口成功、空列表或静态推导代替数据准确性验证。
- **二期 A：直接准备 ADS**。本次只验证 ADS/API 查询层，且没有需要覆盖的 ETL 加工逻辑变更时，准备 ADS 测试数据后验证 ADS 与目标接口。
- **二期 B：ETL 端到端**。本次涉及 ETL 转换、计算、关联、聚合等加工逻辑时，从真实 ETL 上游输入层准备数据，按依赖执行 UAT ETL，再验证最终 ADS 与目标接口。
- A/B 由实际变更链路和验证目标决定，不由“新增接口/修改接口”标签决定；新增接口通常不需要 B。二期数据准备、独立 Oracle 和写入执行遵循已确认的 UAT 工具及安全边界，不能扩展到生产。
- 本批只建立一期 Skill 基础规则和二期路由边界，不实施数据造数、数据库 SQL、UAT INSERT 或 ETL 执行。
