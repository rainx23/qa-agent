# 请求构造与断言设计

本文件承载请求契约、UAT 请求约束、参数构造及断言规则。由 SKILL.md 按任务路由加载。

## 请求构造与断言设计

- 请求依据前端实际调用和后端实际契约还原，包括方法、路由、Path/Query/Body、Content-Type、参数类型/默认值/序列化、必要 Header/Cookie 和认证方式。环境与认证优先复用本机已配置的 UAT 信息，不要求用户逐接口重复提供 URL、账号或 Token。
- 当前接口自动化请求执行限定在 UAT 环境；复用本机 UAT baseURL 和认证配置。环境不明确、配置不可用或无法确认请求目标时不执行，绝不切换生产环境弥补缺口。
- 不得使用生产凭据，不在源码、Git、正式用例、普通报告或聊天内容中暴露密码、Token、Cookie 等秘密。工具应从本地配置读取敏感信息，报告只保留必要的脱敏证据。
- 预期必须来自需求、源码行为、接口契约或已确认业务规则，不能根据被测接口实际响应反向生成预期。
- 断言围绕当前场景要证明的业务行为、参数分支、预期异常和必要响应契约设计。可核对通用响应结果，但不能仅凭 HTTP 200、`code=0` 或 `code=50500` 单独判定 PASS/FAIL。
- 默认不对所有响应字段机械执行全量 Schema、必填或类型校验。只有源码存在不同响应分支、历史问题涉及字段/类型/结构、当前改动影响响应契约，或字段本身是场景判定依据时，才增加对应的定向断言。`msg` 仅在提示内容本身有验证价值时断言。
- 预期触发的异常按预期判定：场景明确验证脚本异常，实际按约定返回异常结果可以是 PASS；正常场景意外出现脚本异常则是 FAIL。不能把某个错误码在所有场景中固定解释为失败。

## 请求输入与断言有效性

- **请求只表达当前场景所需条件**：依据前端真实调用和后端实际读取/校验/使用位置构造请求；保留字段名、类型、数组层级、枚举和操作符，不添加无证据的字段，也不为追求请求成功删除或改写契约字段。
- **区分输入语义**：仅当源码对缺省、null、空字符串、空数组、0、false 或显式默认值有不同处理时，才分别构造请求验证；检查前端是否省略字段、传 null、传空值或做了序列化转换，不能把这些形式互相替代。
- **验证默认值时要有对照**：若目标是验证后端/前端默认处理，应比较“未传字段”与“显式传入默认值”的行为；只有源码证明两者语义相同，才允许合并。不得把当前响应值反推为默认值。
- **每条断言必须可解释**：说明预期依据、断言目标（响应字段/结构/错误行为/结果关系）、预期值或关系，以及何种实际结果应判失败。没有独立预期依据的字段，不写猜测性断言。
- **正常场景验证业务行为**：除必要的通用响应契约外，至少有断言能区分目标业务分支是否真正生效；HTTP 200、通用成功码、字段存在、响应非空或请求参数被原样回显，单独都不足以证明业务行为正确。
- **负向场景验证拒绝契约**：对源码/接口契约明确拒绝的输入，断言应核对拒绝行为及稳定的错误标识/结构；提示文案只有在文案本身属于稳定业务要求时才精确断言。不能只断言“有错误”而不确认拒绝原因。
- **集合与排序断言谨慎使用**：只有数据集稳定且预期可独立确定时，才断言精确数量、完整成员或顺序；动态数据场景优先验证过滤/分页/排序规则及可证明的不变量。合成标识返回空集合，只能证明请求路径，不能证明真实数据过滤正确。
- **动态字段避免脆弱断言**：时间戳、随机 ID、请求追踪号、动态文案等字段，除非是本场景目标，不要求固定值；可按契约验证类型、格式、非空条件或字段间关系。
- **禁止弱化断言掩盖能力缺口**：执行引擎不支持某操作符或字段时，不得删除断言、改用语义更弱的检查后仍标记 COVERED；保留原验证目标并标记 MANUAL_VERIFY/UNKNOWN，待确认支持能力或替代方案。
- **无独立 Oracle 时明确边界**：可对请求结构、参数分支和稳定响应契约作出结论；真实金额、数量、过滤集合、关联或聚合正确性必须有独立数据预期。没有 Oracle 时不得以接口自返回值作为自身正确性的证明，应将数据准确性标记 NOT_VERIFIED/BLOCKED。
- **断言必须能发现目标缺陷**：反向检查“若目标逻辑未执行/执行错误，这条断言是否仍可能通过”。若答案为是，应补充有区分力的断言、调整场景，或明确记录当前无法验证的边界；不得把仅检查请求成功的场景计为业务覆盖。
