# 请求构造与断言设计

本文件承载请求契约、UAT 请求约束、参数构造及断言规则。由 SKILL.md 按任务路由加载。

## 请求构造与断言设计

- 请求依据前端实际调用和后端实际契约还原，包括方法、路由、Path/Query/Body、Content-Type、参数类型/默认值/序列化、必要 Header/Cookie 和认证方式。环境与认证优先复用本机已配置的 UAT 信息，不要求用户逐接口重复提供 URL、账号或 Token。
- 当前接口自动化请求执行限定在 UAT 环境；复用本机 UAT baseURL 和认证配置。环境不明确、配置不可用或无法确认请求目标时不执行，绝不切换生产环境弥补缺口。
- 不得使用生产凭据，不在源码、Git、正式用例、普通报告或聊天内容中暴露密码、Token、Cookie 等秘密。工具应从本地配置读取敏感信息，报告只保留必要的脱敏证据。
- 预期必须来自需求、源码行为、接口契约或已确认业务规则，不能根据被测接口实际响应反向生成预期。
- 断言围绕当前场景要证明的业务行为、参数分支、预期异常和必要响应契约设计。可核对通用响应结果，但不能仅凭 HTTP 200、`code=0` 或 `code=50500` 单独判定 PASS/FAIL。
- 默认不对所有响应字段机械执行全量 Schema、必填或类型校验。只有源码存在不同响应分支、历史问题涉及字段/类型/结构、当前改动影响响应契约，或字段本身是场景判定依据时，才增加对应的定向断言。`msg` 仅在提示内容本身有验证价值时断言。
- 预期触发的异常按预期判定：场景明确验证脚本异常，实际按约定返回异常结果可以是 PASS；正常场景意外出现脚本异常则是 FAIL。不能把某个错误码在所有场景中固定解释为失败。
