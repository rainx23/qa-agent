# Knowledge Management（P4）｜检索与增量维护

## 目标与已实施边界

P4 是跨业务模块的可选知识辅助能力，不替代 P1 的需求/Oracle、P2 对指定 SHA 的源码和当前 DEV 配置核验、P3 SQL 设计。P1/P2/P3 不强依赖 P4：知识未命中、过期、不可用时原任务仍继续，不能把“没有知识”解释为业务不存在或开发漏做。


当前按需路由：
- **只读查询/知识辅助定位**：执行本文件「业务语义定位」「只读按需检索」「状态、证据与返回」三个章节，**不读取写入规则**，不更新文件。
- **用户明确要求建立、补充、更新特定模块知识**：先按本文件定位，再完整读取 `references/knowledge-update.md` 执行 AI 发现、去重、原结构局部编辑、证据与业务验收交付。用户的自然语言模块知识维护指令即为本次范围授权，不需逐条审批；不延伸至未授权模块/Tab。
- **当前任务确需确认旧知识在指定源码版本/DEV 配置下是否仍适用，或发现新旧证据冲突**：额外按需读取 `references/knowledge-freshness.md`，只复核本次受影响的对象。只读任务只报告适用性、不写 JSON；用户明确授权知识维护时再按更新规则局部修订。不要每次检索自动查 Git/DEV。
- P1/P2/P3 **自动触发沉淀的工作流接入、持续/定时新鲜度扫描、跨 Skill 端到端验收仍未实施**；本文件存在不意味着所有主 Skill 已自动写知识。与 P1/P2/P3 混合任务不得为写知识而增加强制 Git/MCP 调用或阻断主任务。

本能力只使用新版工程内 `knowledge/modules/` 的 Markdown/JSON 与执行环境已有文件工具；不依赖专属 Agent API、数据库、向量库、后台扫描、旧工程或平台写入。

## 业务语义定位

1. 从用户需求及任务上下文提取模块、业务动作、页面/Tab、变体、维度、字段/指标、查询模式及预期结果。口语名、历史称呼、技术 Code 只是线索；结合稳定业务对象及实际关联，不要求用户说出精确 pageType/接口 Code。
2. 不把同名、相近名称、共享 API 当作对象同一性的充分证据。页面、配置、组件、API、源码支持多对多关系，需以实际引用/绑定或来源判断；无法唯一定位时列有证据的少量候选和 `UNKNOWN`，必要时只问最关键的一个信息。
3. 对历史叫法优先匹配既有稳定业务对象，不因产品用词不一致重复创建对象。

## 只读按需检索

知识根目录为 `knowledge/modules/`，以业务模块划分，不在通用规则中硬编码任何具体业务模块或仓库。未知模块时先查看实际存在的目录；目录不存在或不可读分别给 `NO_MATCH`/`KNOWLEDGE_UNAVAILABLE`，只读任务不得擅自创建。

1. 先读目标模块 `README.md`（如有）了解已确认范围、历史归档及验收边界。
2. 仅按问题选择相关分类：`business-rules.json`（规则）、`pages-functions.json`（页面）、`interactions-fields.json`（交互/字段/条件）、`interfaces-configs.json`（接口/配置）、`code-data-locator.json`（代码/数据入口）、`quality-experience.json`（历史问题与经验）。
3. 通常先检索 1–2 类，沿实际 ID、pageType、接口或配置 Code、对象绑定按需补读；大 JSON 采用定位搜索/只读解析，不一次加载六类全部内容。历史归档仅在追溯时定向读取，不作为当前正式知识源。
4. 优先用已存对象 ID、技术 Code、仓库＋路径定位；原 JSON 未统一 ID/状态时保留当前结构，不杜撰现有身份和状态。

## 状态、证据与返回

- `formal_reusable` 是来源与适用范围均足够的正式可复用知识；必须区分用户确认、需求文档、源码 SHA、配置环境和真实运行验证，技术事实不等于业务期望。
- `candidate_pending_verification` 与既有 `pending_user_review` 是候选或业务待确认；冲突、环境/SHA 变更未复核时为待复核（新知识可使用 `review_required` 及冲突原因）；旧记录状态缺失时为未知，不能自行升级。
- **SHA 不同不等于相关知识实际失效**；需要当前有效性时按 `references/knowledge-freshness.md` 核查关联源码/配置证据。核不出来的当前适用性返回 `UNKNOWN`，不因为旧 SHA 不同自行判定代码逻辑已变化，也不把历史 DEV 快照冒充当前配置。
- 质量经验 `resolved` 不代表实际运行 PASS，`runtime_validation=not_run` 不能被推断为通过。历史冻结 SHA/DEV 快照不自动代表当前生产或灰度实际部署。P2 自行核实本任务 SHA；P1 不因 P4 而 Fetch。
- 页面默认条件区分 UI 显示值、实际发送并生效的参数、后端固定过滤；只有证据证明生效的条件才适合 P3 SQL。未知条件标 UNKNOWN。
- 回答用“命中对象及适用场景 → 已知结论 → 正式/候选/待复核/未知 → 文件/对象定位与必要来源 → 未验证内容”；只返相关信息，不倾倒整个 JSON。

工具失败或缺失时解释影响范围，不无限重试；主任务继续。只读检索**不得触发写入**。具体维护流程另见 `references/knowledge-update.md`；其中的自动写入限用户明确的业务知识维护范围，不等于未经验证的业务验收 PASS。
